# SkillBridge

**Exchange Knowledge. Unlock Potential.**

A skill-swap and peer-learning platform being built incrementally for a Software Engineering project.

## Current scope
Phase 1 foundation only: Next.js App Router scaffold, full database schema, baseline read-only RLS, Auth profile bootstrap trigger, route inventory, domain primitives, database tests and engineering plan. The root page clearly states development status. Registration, listing CRUD, exchange/booking workflows and external integrations are not yet implemented. Do not treat this package as production-ready.

## Stack
Next.js / React / TypeScript; Tailwind CSS and shadcn configuration; Supabase PostgreSQL/Auth/Storage/Realtime target; React Hook Form/Zod, Lucide and Motion dependencies. Resend, Razorpay and authenticated Jitsi remain optional future integrations. Exact compatible versions are in `package.json` and `package-lock.json`.

## Prerequisites and installation
Node.js 24.x and npm. Docker is needed only for a full local Supabase stack; isolated PostgreSQL tests run without Docker. GitHub and Vercel accounts are needed for publication.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Open http://localhost:3000. The Phase 1 development page renders without external configuration. Supabase operations fail closed until URL and publishable key are provided.

## Environment
Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` from the intended Supabase project's Connect panel. Set `APP_ORIGIN` to the exact application origin. Only publishable credentials may use `NEXT_PUBLIC_`. Server secrets go in ignored `.env.local` locally and Vercel's protected environment settings when hosted. Never commit credentials. The optional integration settings in `.env.example` are reserved contracts; setting a flag does not create an integration that has not been implemented.

## Database
`supabase/config.toml` was generated by the pinned CLI. The foundation migration creates all required entities, constraints, indexes, policies and the registration trigger. End-user writes remain denied until subsequent phases add tested mutation policies/RPCs.

Local (requires Docker):

```bash
npx supabase start
npx supabase db reset
```

`db reset` destroys local development data; use it only for a disposable local database. Never run a remote reset.

For a dedicated hosted project, authenticate using Supabase's supported local flow, select the correct project, inspect existing tables, then:

```bash
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push --dry-run
npx supabase db push
```

The connected-project migration may instead be applied using Supabase's migration tool. Do not apply the same migration twice under different names. Keep `private` out of exposed schemas. Configure Auth site URL and callback allowlists in Phase 2; Storage policies and Realtime publication will be added in Phase 5. No production sample users or passwords are included. See `docs/VERIFICATION.md` for the actual hosted status.

## Commands and checks

```bash
npm run typecheck
npm test
npm run build
npm start
```

`npm test` executes real domain checks and runs migrations/constraints/RLS against PGlite's PostgreSQL engine. Its minimal `auth.users` and `auth.uid` fixtures are NOT Supabase authentication integration tests. These checks do not test REST authorization, concurrent connections, Supabase Storage/Realtime, emails, payments or browsers. Full multi-user Playwright tests are specified in `docs/IMPLEMENTATION_PLAN.md` and will be implemented with those workflows.

## Deployment plan
After functional acceptance gates pass:

1. Create/connect the GitHub `skillbridge` repository and push the complete source plus lockfile, excluding `.env.local` and build output.
2. Import into Vercel, framework Next.js, Node 24, install `npm ci`, build `npm run build`.
3. Configure separate preview/production Supabase projects and environment variables. Apply reviewed migrations before promoting dependent code.
4. Set Supabase Auth site URL and exact callback URLs for the deployment. Configure email verification, password recovery and optional Google OAuth.
5. Configure and sandbox-test optional Resend/Razorpay/authenticated Jitsi integrations before enabling them; otherwise keep their controls unavailable.
6. Require CI checks and actual E2E verification; deploy a preview, verify sign-up through review and ledger reconciliation, then release production.
7. Record the real live URL, deployed commit and verification evidence. A successful foundation build is not evidence that the platform is deployed.

## Troubleshooting
- Missing Supabase configuration: copy `.env.example` and provide the two public settings; never substitute a secret key.
- No writes allowed: expected in Phase 1, not a reason to disable RLS.
- Relation/function errors: verify the intended migration and project; never execute random production SQL to unblock a UI.
- Docker unavailable: use `npm test` for foundation checks; full local Supabase integration tests need Docker or a dedicated hosted test project.
- Dependency resolution: use `npm ci`; do not force incompatible peer dependencies. Resolver v6 had an optional Effect peer conflict during initial setup, so the compatible v5 release is pinned.
- Session errors: confirm callback allowlists, environment URLs and the SSR proxy; do not cache authenticated responses.
